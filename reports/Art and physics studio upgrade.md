# Build four studios on one Metal core

AWIeffect can beat ibis Paint X with a smaller build than it looks, because all four requested studios sit on a few shared parts: **a stamp-based brush engine writing to tiled Metal textures, an 8-bit mask type used for selections, cutouts and eraser strokes, a triangle mesh textured with a layer's original pixels, and one XPBD particle-and-constraint solver**. ibis Paint's gap is not missing features. It has 15 tools, 28 blend modes, 8 rulers and frame animation. Its gaps are ads and export limits, shallow brushes next to Procreate, weak animation, and a cutout that lives in a credit-gated filter instead of the workflow ([Unstar ranking 2026](https://unstar.app/blog/procreate-ibis-paint-sketchbook-adobe-fresco-concepts-drawing-apps-ranked-2026); [ibisPaint Smart Features](https://ibispaint.com/lecture/index.jsp?no=209)). The plan below matches ibis parameter for parameter, takes Procreate's stroke pipeline and Clip Studio's fill, and then adds what no mobile drawing app has: animation frames that are real clips on the AWIeffect timeline, AE Roto Brush-style correction strokes over Apple Vision masks, an AE-style Puppet built on Igarashi's as-rigid-as-possible (ARAP) solver, and Blender-named physics that bakes into keyframes. Build in this order: canvas core and eraser, then layers and selection, then fill and rulers, then animation, then cutout, then puppet, then physics. Each phase ships something usable and reuses the phase before it.

## The ibis Paint spec is concrete enough to clone, and three things beat it

The official manual gives the target in detail. The **Tool Select window has 15 tools** (Transform, Magic Wand, Lasso, Filter, Brush, Eraser, Smudge, Blur, Special Pen, Bucket, Vector, Text, Frame Divider, Eyedropper, Canvas). The main toolbar has Brush/Eraser toggle, Tool Selector, Properties, Color, Fullscreen, Undo, Redo, Layer and Back. An upper-right strip holds Selection Area, Stabilizer, Shape, Ruler and Material ([ibisPaint Toolbar](https://ibispaint.com/lecture/index.jsp?no=04)). The gestures matter as much as the tools. **Two fingers pan, pinch-zoom and rotate together. Two-finger tap undoes and three-finger tap redoes. A second finger touching down during a stroke cancels that stroke** ([ibisPaint Gestures](https://ibispaint.com/lecture/index.jsp?no=151)). Build this recognizer first. It is cheap, and it is most of what makes ibis feel like ibis. Add press-and-hold for the eyedropper with an adjustable delay (ibis added that setting in v13.0).

ibis brushes have a deep parameter set grouped into Fade, Shape, Jitter, Scatter, Type, Texture, Dynamic and Settings. Fade sets thickness and opacity at the start and end of a stroke, plus blur. Shape covers pattern, spacing as a percent of thickness, initial angle, follow-rotation, aspect, opacity saturation and MSAA. Jitter varies position, thickness, opacity, spacing and angle. Scatter sets particle size, density and deviation. Texture sets scale and angle and whether it moves with the stroke, plus invert. Type picks Mono, Water (mixes with color below), Double (outline or shadow) or Color. Dynamic maps speed and pressure to thickness, opacity and blur ([ibisPaint Brush Parameters](https://ibispaint.com/lecture/index.jsp?no=118)). ibis pressure response is a set of signed amounts, not a curve. **A real pressure curve editor is an easy win.** Procreate also maps tilt, azimuth and barrel roll ([Procreate Brush Studio](https://help.procreate.com/procreate/handbook/brushes/brush-studio-settings)). The ibis Stabilizer has two methods. Real Time comes in Constant and Fast Strokes variants, and After smooths the whole line when the pen lifts. Force Fade sets start and end taper length with a Smooth or Linear tip ([ibisPaint Stabilizer](https://ibispaint.com/lecture/index.jsp?no=50)). AWIeffect should also offer Lazy Nezumi's modes. Pulled String keeps sharp corners. Moving Average has a Catch Up option. Weighted is a mass-spring follower that gives the brush inertia ([Lazy Nezumi](https://lazynezumi.com/smoothing)).

Procreate-grade feel comes from three engine choices. First, **render the active stroke into its own offscreen texture, then composite it onto the layer each frame and bake it in on pen-up**. This is what lets a stroke have one opacity cap and glaze or blend modes. Second, use `coalescedTouches` for the full Pencil sample rate. Draw `predictedTouches` only into a throwaway overlay. When `touchesEstimatedPropertiesUpdated` delivers late force values, re-stamp the tail of the stroke ([WWDC15 233 notes](https://wwdcnotes.com/documentation/wwdc15-233-advanced-touch-input-on-ios/); [Apple: estimatedProperties](https://developer.apple.com/documentation/uikit/uitouch/estimatedproperties.md)). Third, support two grain modes, moving (sampled along the stroke's length) and texturized (sampled in canvas space) ([Procreate Brush Studio](https://help.procreate.com/procreate/handbook/brushes/brush-studio-settings)). The pipeline runs in this order: coalesced touches, then the stabilizer, then a Catmull-Rom fit, then arc-length resampling at spacing × size, then instanced dab quads into the stroke texture. Procreate's Silica M engine is pure Metal, so this approach is proven on iOS ([Procreate 4](https://procreate.com/insight/2017/meet-procreate-4)).

For the Water and smudge brush type, follow Krita: keep **Color Rate (how much paint goes in) separate from Smudge Length (how much canvas color gets picked up)**, and use spacing of 0.05 or less for smearing brushes ([Krita Color Smudge](https://docs.krita.org/Color_Smudge); [KDE bug 353665](https://bugs.kde.org/show_bug.cgi?id=353665)). Each smudge dab reads the canvas under it, so smudge dabs that overlap must be drawn one at a time. Batch only the dabs that do not overlap.

**The eraser bug is a data-model problem, not a brush problem.** In ibis, the eraser uses the same settings window and brush patterns as the brush, and erasing returns pixels to transparent on whatever layer is current ([ibisPaint Undo and Eraser](https://ibispaint.com/lecture/index.jsp?no=08)). Imported photos are ordinary raster layers there ([Layer Window](https://ibispaint.com/lecture/index.jsp?no=156)). So the eraser should be the brush engine with a destination-out composite, sharing every parameter. Every layer type must then be able to give the eraser editable pixels. Photos, video stills, text and stickers each need either a real raster texture or a mask texture that the eraser writes into. A mask is better for text and video, because the source stays editable and the erase can be undone. Vector layers should rasterize when erased, or take a CSP-style "erase up to intersection" vector eraser ([CSP Eraser](https://help.clip-studio.com/en-us/manual_en/240_brushes/Eraser_tools.htm)). Add the other ibis erasers as variants: Eraser Bucket, Surrounding Eraser and Lasso Eraser.

## Layers, selections and fill all write one mask type

ibis keeps the selection as a special pink "Selection Layer" at the top of the stack. Painting on it adds to the selection ([ibisPaint Selection Layer](https://ibispaint.com/lecture/index.jsp?no=24)). Copy this exactly. **Store the selection as one R8 texture that lasso, wand, color range, shapes and brush all write to.** Then Invert, Expand/Contract and Feather are each one shader. Feather is a Gaussian blur through `MPSImageGaussianBlur`, and Expand/Contract is `MPSImageAreaMax` or `MPSImageAreaMin`. Lasso has Set, Add and Subtract modes. Add Intersect, plus rectangle and ellipse selection, which the fetched ibis pages did not confirm ([ibisPaint Lasso](https://ibispaint.com/lecture/index.jsp?no=09)). Each layer has clipping (clips to the layer below), alpha lock (edits only opaque pixels, and is not allowed on folders or vector layers) and opacity. The command menu includes White to Transparent and Select Opacity (selection from the layer's alpha), and there are 28 blend modes from Normal through Luminosity ([Layer Window](https://ibispaint.com/lecture/index.jsp?no=156); [Blend modes](https://ibispaint.com/lecture/index.jsp?no=83)). Clipping and alpha lock both work in the composite shader. Clipping multiplies a layer's alpha by its base layer's alpha. Alpha lock writes `dst.rgb = mix(dst.rgb, src.rgb, src.a); dst.a unchanged`. The Transform tool needs Translate-Scale, Perspective and Mesh modes, with Nearest, Bilinear, Bicubic and Lanczos2/3 resampling ([ibisPaint Transform](https://ibispaint.com/lecture/index.jsp?no=154)).

**The magic wand and the bucket are one algorithm with two outputs.** ibis says so directly: the wand's settings mirror the bucket's ([Bucket details](https://ibispaint.com/lecture/index.jsp?no=82)). The bucket settings are Strength (tolerance), Expansion (default 1.5 px, can be negative), Unpainted Recognition, Gap Recognition, Continuous Filling (swipe to fill), Under Line, Boundary (RGBA or Opacity) and Reference Layer (Canvas, Current or a specific layer). With Expansion at 0 px, fills leave gaps at anti-aliased edges. Clip Studio adds "Refer other layers", which skips hidden layers, and a Close gap setting. The trade-off is that a large Close gap value also reads lines that are merely close together as gaps, so users set it to 7–15 ([CSP fill basics](https://tips.clip-studio.com/en-us/articles/590); [CSP closed area fill](https://tips.clip-studio.com/q/articles/591)). The recommended algorithm is a design choice; no vendor source documents its internals. It has six steps. (1) Composite the reference layers. (2) Build a barrier mask from ΔE in OKLab, which matches perceived color better than RGB distance. (3) Dilate the barrier by the gap radius r. (4) Scanline flood fill from the seed, on the CPU or as a GPU jump-flood. (5) Dilate the result by r again so it reaches back under the lines. (6) Use the line art's alpha as fill coverage at the border, so the edge is anti-aliased instead of a hard mask. The wand stops after step 5 and writes to the selection mask instead of the layer. ibis users report wand problems, which most likely come from skipping the reference-layer and expansion steps. That cause is inferred; the notes do not confirm it.

The 8 rulers (Straight, Circular, Elliptical, Radial, Mirror, Kaleidoscope, Array, Perspective Array) and the shape tools all fit one pattern ([Mirror Ruler](https://ibispaint.com/lecture/index.jsp?no=47)). **Project each stabilized point onto the constraint before resampling it into dabs.** Mirror and Kaleidoscope instead emit 2–N transformed copies of each dab. Krita's wrap-around mode adds seamless textures cheaply: sample with `address::repeat` and wrap dab positions modulo canvas size ([Krita View menu](https://docs.krita.org/ja/_sources/reference_manual/main_menu/view_menu.rst.txt)). Procreate's QuickShape (draw and hold to snap to a clean shape) is a dwell timer around 0.5 s that runs least-squares line, Fitzgibbon ellipse and Ramer–Douglas–Peucker polygon fits and picks the best fit ([Procreate 4.2](https://procreate.com/insight/2018/procreate-update-42)). Liquify keeps a displacement field with ibis's Drag, Shrink, Expand, Smoothen and Revert modes ([Liquify Pen](https://ibispaint.com/lecture/index.jsp?no=138)).

For storage, Krita's model fits: **tiled layers with copy-on-write tile snapshots for undo, and a memory budget that moves old undo states to disk** ([Krita Transactions](https://community.kde.org/Krita/Transactions_Design); [Krita Performance](https://docs.krita.org/Performance_Settings)). Use 256×256 tiles. On pen-down, blit the tiles the stroke touches into an undo record and LZ4-compress it in the background. Cache composites of the layers below and above the active layer, so painting costs three draws however many layers there are. Apple forum developers report that Metal canvases slow down as they fill up, and these caches are the fix ([Apple Developer Forums](https://origin-devforums.apple.com/forums/profile/kyroneus/replies)). Crash-safe autosave journaling also answers the top complaint about every drawing app, which is losing hours of work.

For animation, match ibis and Procreate, then hook into the host app. ibis has fps, frame duration, duplicate and delete, onion skin (count, first and last opacity, color) and Loop, Ping-pong and One-shot playback. Its Video Mode converts to a 60 fps clip-on-track timeline, and that conversion cannot be undone ([ibisPaint animation](https://ibispaint.com/lecture/index.jsp?no=182); [Video Mode](https://ibispaint.com/lecture/index.jsp?no=210)). Procreate allows up to 12 onion-skin frames, red for previous and green for next, plus per-frame hold durations ([Procreate Animation](https://help.procreate.com/procreate/handbook/animation/animation-interface)). **AWIeffect's advantage is that a drawing sequence becomes a native clip, with no one-way conversion.** Each drawn frame is a held image on a timeline the editor already has. Onion skin draws in the studio over the real video frame under it, which gives rotoscoping over footage for free. Add a CSP-style light table that pins any chosen frame as reference.

## Cutout should be Vision masks, AE-style correction strokes and temporal smoothing

**For stills and keyframes, use `VNGenerateForegroundInstanceMaskRequest`.** It runs on iOS 17+, works on any kind of subject, labels instances from 1 with 0 as background, and supports tap-to-pick. For people in video, use `VNGeneratePersonSegmentationRequest`: .balanced for preview and .accurate for export. Call Vision directly rather than through VisionKit, which runs out of process and limits image size ([WWDC23 10176](https://wwdcnotes.com/notes/wwdc23/10176); [Apple quality levels](https://developer.apple.com/documentation/vision/vngeneratepersonsegmentationrequest/qualitylevel-swift.enum.md); [Kodeco](https://www.kodeco.com/29650263-person-segmentation-in-the-vision-framework?page=2)). ibis's Background Removal is point-prompted, with blue keep points and red background points ([ibisPaint Background Removal](https://ibispaint.com/lecture/index.jsp?no=177)). AWIeffect beats it by offering points and a brush. The in-studio AI cutout and the clip cutout should be the same component, and the output should be a mask, not destructive pixels. The Draw Studio then gets "Cut out subject" as a layer mask, and the eraser keeps working on top of it. Instance labels are not stable across frames, so on each later frame re-pick the instance that overlaps the warped previous mask most.

The UX to copy is AE Roto Brush. The user paints foreground strokes on a base frame, propagates forward and backward, and paints corrections on any frame. Each correction becomes a new key that re-propagates. Freeze caches the result. The matte controls are Feather, Contrast, Shift Edge, Reduce Chatter, Motion Blur (8 samples, 180° shutter by default) and Decontaminate Edge Colors ([FilmDaft Roto Brush](https://filmdaft.com/roto-brush-tutorial-part-2-after-effects-advanced/); [Adobe Learn Refine Edge](https://www.adobe.com/learn/after-effects/web/roto-brush-refine-edges)). CapCut stops at one tap, and its own guidance admits that hair, hands, contact points, motion blur and same-color clothing need manual review ([CapCut](https://www.capcut.com/create/capcut-background-removal-player-cutout-reels)). **Use AE's control names exactly** so editors trained on AE can map them instantly. Use a green add / red subtract toggle in place of the Alt key, and show keyed frames as diamonds on the timeline. Store strokes, not just pixels, so propagation can rerun when the models get better. The data model has three parts: the auto mask per frame, sparse stroke keys (add, subtract or refine, each with radius and hardness), and global refine parameters. Cache the baked masks as 8-bit images per frame. When a key changes, invalidate only the frames between the previous key and the next one.

**Flicker comes from per-frame masks that know nothing about the frames around them, and the fix comes in two tiers.** Tier A runs on every device. Warp the previous mask with `VNGenerateOpticalFlowRequest`. Blend it with the current mask using an EMA weighted by confidence, about 0.6 on the current mask where the flow is consistent and lower where it is not. Then run a guided filter against the full-resolution frame, about r = 8 and ε = 1e-4, built from box filters in Metal ([Apple optical flow](https://developer.apple.com/documentation/vision/vngenerateopticalflowrequest.md)). Tier B runs on A17 and later and uses a SAM2-family tracker with memory. **EdgeTAM runs at 16 FPS on iPhone 15 Pro Max, against roughly 1 FPS for SAM 2**, and EfficientTAM runs at about 10 FPS but is the least accurate on fast motion ([EdgeTAM](https://huggingface.co/facebook/EdgeTAM); [FMOX review](https://www.themoonlight.io/fr/review/benchmarking-sam2-based-trackers-on-fmox)). MobileSAM is available as a 19 MB Core ML model, and Apple publishes Core ML SAM 2.1 ([MobileSAM-CoreML](https://huggingface.co/mlboydaisuke/MobileSAM-CoreML); [apple/coreml-sam2.1-large](https://huggingface.co/apple/coreml-sam2.1-large)). With a tracker, correction strokes become positive and negative prompts plus a new memory frame. Without one, warp the mask delta the user drew along the optical flow, fading it with each frame, until the next key. Recurrent matting is the reason RVM does not flicker ([RVM paper](https://openaccess.thecvf.com/content/WACV2022/papers/Lin_Robust_High-Resolution_Video_Matting_With_Temporal_Guidance_WACV_2022_paper.pdf)), but **RVM is GPL-3.0 and ships only fixed 720p and 1080p Core ML models, which makes it a licensing blocker** for a closed App Store app ([RVM listing](https://awesome.ecosyste.ms/projects/github.com%2FPeterL1n%2FRobustVideoMatting)). The licenses for MODNet and EdgeTAM were not verified. Check them before shipping. Multi-model pipelines such as MatAnyone run out of memory on iPhones unless the models load one at a time, so the app needs a model manager that unloads them ([MatAnyone-CoreML](https://huggingface.co/mlboydaisuke/MatAnyone-CoreML)).

The refine chain is a series of Metal post passes, each mapped to an AE control. Shift Edge is morphology, or a threshold on a distance field for sub-pixel shifts. Feather is a Gaussian on alpha. Contrast is a smoothstep around 0.5. Reduce Chatter is a temporal EMA or median. The Refine brush runs a guided filter only inside a band the user paints, made by dilating and eroding the mask. Decontaminate estimates the foreground as F = (I − (1−α)B)/α, with B taken from blurred pixels outside the mask. One AE user reports flicker-free results with Reduce Chatter at 100% and Chatter Reduction set to Smoother ([Adobe Community](https://community.adobe.com/t5/after-effects-beta-discussions/rotobrush-3-now-available-in-the-after-effects-beta/td-p/13984477)). That supports making temporal smoothing the default rather than an option. Offer AE's overlay views: red onion, black-and-white alpha, checkerboard, and on black or white.

## Puppet needs ARAP, five pin types and a hard mode split

AE's Advanced Puppet engine (AE 2019 and later) has five pin types. **Position pins move a point. Advanced pins also rotate and scale around their own center. Bend pins rotate and scale but cannot move. Starch pins stiffen an area. Overlap pins set which parts draw in front.** Mesh density is set by Triangles, and Expansion grows the mesh past the alpha edge ([No Film School](https://nofilmschool.com/2018/10/adobe-after-effects-2019-has-new-puppet-tools-and-they-are-badass); [AEJuice](https://aejuice.com/blog/how-to-increase-the-control-area-of-a-rig-in-adobe-after-effects/); [Kelley tutorial](https://tutorials.nmdprojects.net/ae_puppet/script/kelley_aepuppet.html)). The math to use is Igarashi, Moscovich and Hughes (SIGGRAPH 2005). It solves in two closed-form linear steps: first a rotation per triangle, then an adjustment that fixes scale. It is real time on meshes of a few hundred triangles ([Igarashi 2005](https://www-ui.is.s.u-tokyo.ac.jp/~takeo/papers/rigid.pdf); [JGT 2009](https://www-ui.is.s.u-tokyo.ac.jp/~takeo/papers/takeo_jgt09_arapFlattening.pdf)). Adobe has not said whether AE uses this algorithm, so treat Igarashi as a proven method, not a copy of AE.

The implementation reuses parts that earlier phases already built. Take the mesh from the layer or cutout alpha. Trace the contour with marching squares, simplify it with Douglas-Peucker, offset it by Expansion, and run a constrained Delaunay triangulation sized from Triangles. Draw the mesh as textured triangles with the original UVs, so the art stays sharp. **Factor the solver's matrices with Accelerate `SparseFactor` only when the set of pins changes. Each frame then needs only back-substitution, which is well under a millisecond for about 500 vertices** (an estimate, not a benchmark). Starch adds weight to rigidity in the triangles it covers. Advanced and Bend pins constrain a small ring of vertices to a rotation and scale target. Overlap stores a depth for each triangle, and the triangles draw with a depth test. AE users report that Starch alone cannot stop unwanted bending, and that too many pins kill natural deformation ([Adobe Community](https://community.adobe.com/questions-529/puppet-tool-help-new-starch-69220)). So expose a Rigidity slider per area, and keep jointed rigs (one puppet per part, parented) as a documented workflow. Each pin's position, plus rotation and scale for Advanced and Bend, keys through AWIeffect's existing easing system. Add AE-style sketch recording: hold Record and drag, the app samples at playback rate, then thins the samples into keys.

The toggle between placing pins and moving pins answers the most common mobile frustration, where a tap meant to drag adds a pin by accident. **Place mode: a tap on the mesh adds a pin of the selected type. Move mode is the default: a tap only selects, a drag only moves, and the hit radius is about 44 pt.** In Move mode, a long-press offers "Add pin here". Every pin add is its own undo step. Draw pins large with a color and icon for each type, and add a Show Mesh toggle. Because the cutout mask feeds the mesh directly, "cut out character, then wiggle it" becomes one flow. Alight Motion has no documented puppet tool ([Habr Q&A](https://qna.habr.com/q/926087)), so this would set AWIeffect apart among mobile editors.

## One XPBD core runs every Blender material except slime

Use Blender's names in the UI, because users already know them from tutorials. Soft bodies use **Goal** (the shape the body tries to return to), Goal Stiffness and Goal Damping. Edges have Pull, Push, Damp, Plasticity, Bending and Length. Collision has Collision Damping (0 = full bounce, 1 = none) ([Blender Soft Body Goal](https://docs.blender.org/manual/en/latest/physics/soft_body/settings/goal.html); [Edges](https://docs.blender.org/manual/en/latest/physics/soft_body/settings/edges.html); [Collision](https://docs.blender.org/manual/en/latest/physics/collision.html)). Cloth uses Tension, Compression, Shear and Bending, plus Pin Group and Pressure for inflated shapes ([Cloth Physical Properties](https://docs.blender.org/manual/en/latest/physics/cloth/settings/physical_properties.html); [Cloth Shape](https://docs.blender.org/manual/en/latest/physics/cloth/settings/shape.html)). Rigid bodies use Bounciness from 0 to 1, Friction, collision Shape, and constraints Fixed, Point, Hinge, Slider, Piston, Generic Spring and Motor ([Rigid Body Collisions](https://docs.blender.org/manual/en/latest/physics/rigid_body/properties/collisions.html); [Constraints](https://docs.blender.org/manual/en/latest/physics/rigid_body/constraints/index.html)). Liquids use Viscosity and Surface Tension ([Liquid Diffusion](https://docs.blender.org/manual/en/latest/physics/fluid/type/domain/liquid/diffusion.html)). Force fields include Force, Wind, Vortex, Magnetic, Harmonic, Turbulence and Drag, with falloff by shape and distance ([Force Fields](https://docs.blender.org/manual/en/latest/physics/forces/force_fields/index.html)). Blender's own SPH particle physics is described as covering "liquids to slime" ([Particle Fluid](https://docs.blender.org/manual/en/latest/physics/particles/emitter/physics/fluid.html)).

**The engine is XPBD with many substeps of one iteration each.** Its compliance term α/Δt² keeps stiffness the same whatever the timestep or iteration count ([XPBD paper](https://matthias-research.github.io/pages/publications/XPBD.pdf)). One particle-and-constraint core then covers four material families. Rope and cloth are distance and bending constraints. Soft bodies and jelly are Müller shape matching, which pulls particles toward a rigid fit of the rest shape: it is Blender's Goal, with α of 0.1–0.3 for wobbly jelly and 0.8 or more for rubber. Layer soft bodies are distance plus area constraints on the puppet mesh. Rigid-ish bodies are stiff shape matching or a small rigid solver with joints. Ten Minute Physics has a reference implementation for nearly every piece: XPBD basics, unbreakable soft bodies, spatial hashing, cloth, self-collision, FLIP water and joints ([Ten Minute Physics](https://matthias-research.github.io/pages/tenMinutePhysics/index.html)). **Liquid is Position Based Fluids (PBF) on the same particles.** It solves a density constraint with relaxation ε, adds an artificial pressure s_corr (k ≈ 0.1, n = 4) that stops clumping and mimics surface tension, and uses XSPH viscosity of about 0.01 for water and much higher for honey ([PBF slides](https://cgweb.informatik.uni-freiburg.de/intern/seminar/positionBasedFluids_2014_SIGGRAPH.pdf); [PBF paper record](https://history.siggraph.org/?p=108378)). **Slime, goo and snow need 2D MLS-MPM**, because those materials yield and deform permanently, and particle constraints fake that badly. The 88-line Taichi reference covers it with P2G, a grid update and G2P, plus plasticity by SVD clamping. It runs about 3k particles on an 80² grid at dt = 1e-4, and 320² for higher quality ([mls-mpm88-explained](https://github.com/yuanming-hu/taichi_mpm/blob/master/mls-mpm88-explained.cpp)). The particle budgets below are estimates, because no measured iPhone benchmarks exist: PBF at 10k–30k particles at 60 fps, XPBD cloth at 64² with 10 substeps as trivial, and MPM at 20k–50k particles on a 128² grid. Metal mapping uses Jacobi or graph-colored constraint solves, a counting-sort spatial hash, and `atomic<float>` adds for P2G. Clamp each substep's motion to under one particle radius, and damp velocities by (1 − k·dt).

Rendering decides whether the simulation looks good. For fluids, **draw each particle as an additive falloff sprite into a half-resolution R16F buffer, blur it, threshold it with smoothstep, then shade from the field's gradient** with Blinn specular, a Fresnel rim, refraction offset by the normal, and absorption through thickness ([gamedev.net metaballs](https://gamedev.net/forums/topic/484576-efficient-2d-metaballs/4177661/); [NVIDIA screen-space fluids](https://developer.download.nvidia.com/presentations/2010/gdc/Direct3D_Effects.pdf)). NVIDIA notes that large blobs read as "viscous", which works in slime's favor. Soft-body layers reuse the puppet mesh, so text and images stay sharp while they wobble. **Bake with a fixed timestep and seeded randomness, so the export always matches the preview.** Cache vertex or particle positions for each frame, invalidate the cache when parameters change, and offer "convert rigid body to keyframes" so editors can tweak the motion in the graph editor.

| Rope | XPBD distance chain | High stiffness, low bending | Stroked spline |

The soft-body, slime and liquid values in this table are design starting points, not sourced values. The cloth numbers come from memory of Blender's presets and were not checked against a live page. Tune all of them in the app.

## Ship it in seven phases, each reusing the last

| Phase | Deliverable | Reused by later phases |
|---|---|---|
| 1. Canvas core | Tiled Metal layers, stroke texture, stamp brush with ibis parameters, stabilizers, Pencil coalesced and predicted touches, gestures, eraser on every layer type through raster or mask, tile undo, autosave journal | Everything |
| 2. Layers and selection | 28 blend modes, clip, alpha lock, folders, R8 selection layer, lasso, shapes, wand, Transform modes | Mask type used by cutout and puppet |
| 3. Fill and assists | OKLab bucket with reference layers, gap close and expansion; 8 rulers, QuickShape, Liquify, smudge brush, .brushset import | Wand shares the fill code |
| 4. Animation | Frames as timeline clips, onion skin, holds, playback modes, light table over video | Drawing over footage for roto |
| 5. Cutout | Vision instance and person masks, add/subtract/refine strokes, flow + EMA + guided filter, AE refine controls; EdgeTAM tier after a license check | Mesh source for puppet and physics |
| 6. Puppet | Alpha to mesh, Igarashi ARAP with sparse Cholesky, five pin types, Place/Move toggle, keys plus sketch recording | Mesh for soft-body layers |
| 7. Physics | XPBD core (rope, cloth, jelly, rigid), forces, PBF liquid, MPM slime, metaball shading, bake to cache and keys | — |

These decisions are still open and need in-app checks: Vision and EdgeTAM speed per device in ms per frame, model licenses (RVM is ruled out by GPL-3.0), the exact numeric ranges for AE and ibis controls (Adobe Help pages were blocked during research), and real PBF and MPM particle budgets on A14-class GPUs.

## Conclusion

The architecture rests on one finding. **The four studios that sound separate are three primitives used again and again: masks, meshes and particles.** The eraser bug, the broken wand and the flickering cutout all come from features that each kept their own pixel model. Once eraser strokes, selections and cutouts all write the same R8 mask, and puppet and soft bodies share one alpha-traced mesh, each new feature costs a fraction of the one before. That is why the order above runs from the drawing core outward. AWIeffect's real advantage over ibis Paint is not more tools. It is that the drawing studio, the cutout, the puppet and the physics all output timeline clips and keyframes an editor can keep refining, which no standalone painting app can offer.
